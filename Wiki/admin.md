# TokenPay 后台管理页面

TokenPay 内置一个默认关闭的后台管理页面，用于只读查看订单、钱包和汇率记录。对于用户已经真实完成链上付款、但订单因超时或未能自动匹配而变成 `Expired` 的情况，管理员还可以在核实链上交易后进行人工补单。

## 功能范围

- 分页、筛选和查看 `TokenOrders` 订单记录。
- 查看 `Tokens` 钱包的地址、币种、余额和最后检查时间，并可手动刷新 TRON 钱包余额。后台列表查询不会读取或显示私钥字段 `Key`。
- 查看 `TokenRate` 汇率记录。
- 点击地址或交易哈希可以前往 OKLink 查询，也可以一键复制。
- 对 `Expired` 订单执行人工补单。
- 后台不提供常规数据修改或删除功能。

## 安全设计

- 后台默认关闭。关闭时，整个 `/admin` 路径返回 404。
- 使用独立的 Cookie 登录认证，Cookie 设置为 `HttpOnly` 和 `SameSite=Strict`。
- 生产环境默认要求 HTTPS Cookie。
- 密码通过 ASP.NET Core `PasswordHasher` 生成带随机盐的单向哈希，配置文件中不保存明文密码。
- 每个来源 IP 在 10 分钟内最多尝试登录 5 次。
- 所有修改请求都启用防跨站请求伪造校验（CSRF）。
- 后台响应禁止缓存和页面嵌入，并记录登录成功、登录失败和补单操作日志。
- 钱包列表使用只读字段投影，数据库查询不读取私钥列。

后台安全不能替代服务器安全。请同时使用 HTTPS、防火墙、强密码，并限制服务器管理权限。不要将后台直接暴露在不可信网络中；条件允许时，建议再通过反向代理 IP 白名单或 VPN 限制访问。

## 生成密码哈希

先构建或下载 TokenPay，然后在程序所在目录执行：

```bash
dotnet TokenPay.dll --hash-admin-password "在这里填写你的强密码"
```

如果使用 Windows 可执行文件，也可以执行：

```powershell
.\TokenPay.exe --hash-admin-password "在这里填写你的强密码"
```

命令会输出一行类似下面的内容：

```text
AQAAAAIAAYagAAAAE...
```

该内容是密码哈希，不是原始密码。请使用密码管理器生成至少 20 位的随机密码，并妥善保存原始密码。忘记密码时无法从哈希反向还原，只能重新生成新的哈希。

## 配置并开启后台

编辑 `appsettings.json`：

```json
{
  "Admin": {
    "Enabled": true,
    "Username": "admin",
    "PasswordHash": "粘贴上一步生成的完整哈希",
    "SessionMinutes": 30,
    "RequireHttps": true
  }
}
```

配置项说明：

| 配置项 | 默认值 | 说明 |
| --- | --- | --- |
| `Enabled` | `false` | 是否开放后台管理路径。配置完成前不要开启。 |
| `Username` | `admin` | 后台登录用户名，建议修改。 |
| `PasswordHash` | 空 | 使用上述命令生成，不能填写明文密码。 |
| `SessionMinutes` | `30` | 登录会话有效时间（分钟），活动期间会自动续期。 |
| `RequireHttps` | `true` | 是否仅通过 HTTPS 发送登录 Cookie。生产环境必须保持 `true`。 |

首次配置用户名、密码哈希及 Cookie 选项后，重启 TokenPay，然后访问：

```text
https://你的域名/admin
```

仅在本机通过 HTTP 调试时，可以暂时将 `RequireHttps` 设为 `false`。公网部署时不要关闭此项。如果 HTTPS 在反向代理处终止，请正确配置代理转发协议，让 TokenPay 能识别原始 HTTPS 请求。

如需关闭后台，将 `Enabled` 改回 `false` 即可。程序会动态读取该开关，使用默认的 `appsettings.json` 配置加载方式时通常无需重启；后续请求会直接返回 404。重新设为 `true` 后也会动态恢复访问。

`SessionMinutes` 和 `RequireHttps` 是在应用启动时配置到登录 Cookie 中的，修改这两项后需要重启 TokenPay。修改用户名或密码哈希后，新的登录验证会动态使用新值，但已经签发的登录 Cookie 会继续有效到会话过期。遇到账号泄露等紧急情况时，可以先将 `Enabled` 设为 `false`，这样包括已有登录会话在内的所有后台请求都会立即被拒绝。

## 页面使用说明

### 订单记录

订单页面支持按以下条件组合搜索：

- 外部订单号、用户标识、付款地址、收款地址或交易哈希关键词。
- 订单状态。
- 币种。
- 创建时间范围。

每页可以显示 10、20、50 或 100 条记录。付款地址、收款地址和交易哈希会完整显示，并支持复制或跳转到 OKLink 查询。如果订单存在 `RedirectUrl`，外部订单号可以点击打开对应页面。

### 钱包记录

钱包页面仅展示地址、币种、余额和最后检查时间。私钥不会显示，并且列表查询时不会从数据库读取 `Key` 字段。钱包地址支持复制和跳转到 OKLink；TRON 钱包还可以点击“检查余额”立即刷新链上余额，该操作受后台登录和 CSRF 防护。

当 `UseDynamicAddress=false` 且钱包表没有记录时，导航栏隐藏钱包菜单；启用动态地址或已经存在钱包记录时显示。

### 汇率记录

汇率以 `1 币种 = 汇率 法币` 的形式显示，例如：

```text
1 USDT = 7.20 CNY
```

## 人工补单

人工补单只适用于以下情况：

1. 订单状态已经是 `Expired`。
2. 用户确实完成了链上付款。
3. 系统因为订单超时、金额未匹配或其他原因没有自动识别该付款。
4. 管理员已在对应区块浏览器中确认交易成功、网络和币种正确、收款地址正确且金额一致。

点击订单右侧的“补单”，填写：

- 付款地址：用户实际转出资金的钱包地址。
- 交易哈希（TxID）：从区块浏览器复制的完整交易标识。
- 付款时间：以链上交易时间为准。
- 实付金额：链上实际到账数量，注意右侧显示的币种单位。

提交后会发生以下操作：

1. 订单状态从 `Expired` 变为 `Paid`。
2. 保存付款地址、交易哈希、付款时间和实付金额。
3. 订单进入原有异步商户回调流程。
4. 触发原有管理员到账消息。

补单不会发起任何链上转账，也不会替用户付款。它是在确认资金已经真实到账后，人工修正 TokenPay 中的订单状态。

> **重要：** 不要仅凭用户提供的截图补单。截图可能被伪造，必须亲自在区块浏览器中查询交易哈希。错误补单可能触发商户自动发货，并造成无法追回的损失。

同一个交易哈希不能用于多个订单。如果订单已经不是 `Expired` 状态，后台也会拒绝补单。

## 常见问题

### 登录后又返回登录页

检查是否通过 HTTPS 访问，以及反向代理是否正确转发了请求协议。本机 HTTP 调试可以暂时设置 `RequireHttps=false`。

### 登录提示请求过于频繁

同一个来源 IP 在 10 分钟内最多尝试 5 次。确认用户名和密码后等待限制窗口结束。如果所有用户都显示为同一个 IP，请检查反向代理和转发头配置。

### 忘记后台密码

重新运行密码哈希命令生成新哈希，替换 `PasswordHash`，然后重启 TokenPay。原密码无法从哈希中恢复。

### 配置完成后仍然访问不到后台

确认 `Admin:Enabled` 为 `true` 且 JSON 格式正确。开关会动态生效；后台关闭时访问 `/admin` 会按设计返回 404。如果修改了 `SessionMinutes` 或 `RequireHttps`，则需要重启 TokenPay。
